CREW Client

Not an official Minecraft product. Not approved by or associated with Mojang or Microsoft.

Who makes it

CREW Client is made by Ludovic Marie; reach him through lu4ovic.com (opens in a new tab). This site is developed by Anthony S of DezerX (opens in a new tab), who is responsible for it. CREW Client contains no Minecraft code, assets or data, and this site offers no game files: you need your own legally obtained copy of Minecraft: Java Edition. Minecraft is a trademark of Mojang Synergies AB.

Licences

CREW Client's original work is under the MIT licence (opens in a new tab). The fonts are Geist and Geist Mono, under the SIL Open Font License (opens in a new tab). Every asset on this site is listed in LEGAL.md.

Privacy

This site sets no cookies, has no analytics or trackers and loads nothing from third parties except GitHub. When you open a release, the server keeps a one-way hash of your IP address so that release counts each visitor once; the address itself is never stored. To show the latest releases, patch notes, links and contributors, your browser asks api.github.com and raw.githubusercontent.com for them, and avatars.githubusercontent.com for the contributors' pictures; GitHub's privacy statement (opens in a new tab) covers those requests. The launcher sends nothing unless you allow it: what it can send, and how to delete it (opens in a new tab).

CREW Client APIs

CREW Client has seven surfaces that other programs and people build on. Each one has an API (the contract: what you may call, read or write, and what CREW Client promises about it) and an SDK (the tools that help you use it). This section has one page per surface, plus the rules every surface follows: stability and versioning.

How these APIs are designed

  • From the people who use them. Each API starts from what a mod author, a pack author, a server host or an agent needs to do, written down as tasks ("a host backs up the world from a script"), and from how CREW Client is built: Rust, wgpu and a server thread that runs every world. A function exists because a task needs it.
  • Our own design. CREW Client's APIs are not modelled on any other project's. Contributors may know other mod loaders, renderers and server platforms exist, but their source and API references are never read, copied or paraphrased here, and our names, shapes and docs are not taken from theirs. Vanilla Minecraft 26.3 is the reference for game concepts: ids, commands, server.properties, data packs and resource packs.
  • Safe by default. A content mod is data and runs no code; a native mod runs with the player's rights, so it is off by default, behind a warning and reviewed before the registry lists it; the control sockets listen on this computer only, behind a token; nothing here is on by default where it would change vanilla's look or behaviour.
  • Free when unused. An API nobody uses costs nothing per tick or per frame: no engine, no thread, no allocation.
  • One contract for every mode. In-frame single player, the server thread, LAN and the dedicated server run the same gameplay code (AGENTS.md), so a server-side API serves all of them.

References are generated

A reference page is written by code from the source it describes, and a test fails when the two differ:

PageGenerated fromUpdate it with
server-reference.mdhorizon-server's help, config::TEMPLATE, api::ROUTESHORIZON_WRITE_DOCS=1 cargo test -p horizon-server reference
horizon-ctl-commands.mdthe command table in crates/horizon-client/src/bin/horizon-ctl/commands.rshorizon-ctl help --markdown > docs/horizon-ctl-commands.md
launcher-commands.mdlauncher/src/cli.rsHORIZON_WRITE_DOCS=1 cargo test --manifest-path launcher/Cargo.toml the_launcher_reference
launch-reference.mdcrates/horizon-client/src/game/launch_api.rsHORIZON_WRITE_DOCS=1 cargo test -p horizon-client --lib launch_api

So a pull request that changes an API also changes its reference, and the reviewer sees the API's diff in the reference's diff. The guides (overview, how-to, examples) are written by hand.

Each surface's page

Every page has the same parts: Overview (what you can build), Guide (where to start), Reference, Examples, Stability (the level of each part, per stability.md), Changelog and Not there yet (what is planned, so nobody builds on a guess).

The website shows these pages at playhorizon.dev/docs/api, built from this folder, and a summary for players and authors at playhorizon.dev/docs/apis (in the website's repository, horizon-rust/horizon-site).

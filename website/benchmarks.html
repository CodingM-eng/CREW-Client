About this computer's runs

A 2016 laptop: 2 cores / 4 threads and Intel integrated graphics, Linux with Mesa 26.1.8 (Horizon on Vulkan, vanilla on OpenGL). It has no screen attached, so both games drew to a GPU compositor (sway on the Intel GPU) in a 1280x720 window. Horizon ran two flights per scene, vanilla two separate games of one. Görüş Mesafesi (Chunks) 32 is not shown: in 5 minutes neither game finished loading the spawn, and given 25, Horizon kept only about 900 to 1,400 chunk columns resident on this machine instead of the 3,200 a full view holds, so the two games would not have drawn the same world.

On the ThinkPad laptop, Horizon hitched 242 times a minute against Java Edition's 470. It got into the world 34% faster and used 62% less memory.

How it was measured

Each game starts from a fresh world (seed 1234, creative), waits until every chunk around the spawn is loaded and drawn, then visits a village, a forest, an ocean and a mountain. At each it waits for the terrain, holds for 2 seconds and flies a straight 192-block path in 12 seconds, recording every frame.

VSync off, no frame cap, a 1280x720 window, simulation distance 12, everything else at vanilla's defaults. Java Edition 26.3 runs as players get it, with the official launcher's Java options. Each figure is the median over the runs, measured on 2026-10-22.

The full method and its caveats are in docs/benchmark.md.

Benchmark your own computer

Run this in a terminal. It flies the same path and writes a report to the benchmarks folder of the game folder. Share it on Discord and your machine helps make these numbers better.

horizon-client --benchmark standard --render-distance 12
